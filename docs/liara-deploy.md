# استقرار سرور و پنل مدیریت روی لیارا

سرور مرکزی (API)، پنل مدیریت و وب‌اپ مشتری در یک برنامه Docker روی [لیارا](https://liara.ir) اجرا می‌شوند. پایگاه داده PostgreSQL مدیریت‌شده لیاراست و تصاویر روی یک دیسک لیارا می‌مانند.

| نشانی | بخش |
| --- | --- |
| `https://<برنامه>.liara.run/` | وب‌اپ عمومی مشتری: صفحه شروع، خدمات، تعرفه‌ها و پلن‌ها، بدون فعال‌سازی |
| `https://<برنامه>.liara.run/admin` | پنل مدیریت |
| `https://<برنامه>.liara.run/kiosk` | مدیریت کیوسک‌ها: دانلود برنامه ویندوز، ثبت دستگاه، کلید، فعال‌سازی و وضعیت |
| `https://<برنامه>.liara.run/api/v1` | API |

کیوسک ویندوز روی کامپیوتر کیوسک جداگانه اجرا می‌شود و به `https://<برنامه>.liara.run` وصل می‌شود؛ هر دو به یک API و یک پایگاه داده.

فایل‌های لازم در مخزن آماده‌اند:

| فایل | کار |
| --- | --- |
| `Dockerfile` | ساخت سرور و پنل در یک image |
| `liara.json` | پلتفرم Docker، پورت ۳۰۰۱، ساخت در موقعیت آلمان، اتصال دیسک `media` |
| `.dockerignore` | فایل‌هایی که آپلود نمی‌شوند (از جمله `.env` و `node_modules`) |
| `apps/server/scripts/docker-start.sh` | هنگام هر اجرا: بررسی متغیرها، اعمال migrationهای جدید، داده اولیه، اجرای سرور |
| `apps/server/scripts/startup-failed.mjs` | اگر یکی از این مراحل خطا بدهد، به‌جای خطای ۵۰۲ لیارا صفحه‌ای با علت خطا نمایش می‌دهد |

## ۱. پایگاه داده

1. در کنسول لیارا ← «دیتابیس‌ها» یک PostgreSQL بسازید. هنگام ساخت یک **شبکه خصوصی** انتخاب کنید. برنامه هم باید در **همین شبکه** باشد، چون شبکه بعداً قابل تغییر نیست.
2. در صفحه دیتابیس ← «نحوه اتصال»، **آدرس شبکه خصوصی** (URI) را بردارید. شکلی شبیه این دارد:

   ```
   postgresql://root:<رمز>@<شناسه دیتابیس>:5432/postgres
   ```

## ۲. برنامه

1. «برنامه‌ها» ← «ایجاد برنامه» ← پلتفرم **Docker**، در همان شبکه خصوصی دیتابیس. شناسه برنامه (مثلاً `andishkadeh`) آدرس آن را می‌سازد: `https://andishkadeh.liara.run`.
2. **دیسک:** در صفحه برنامه ← «دیسک‌ها» یک دیسک با نام دقیق `media` (مثلاً ۱ گیگابایت) بسازید. تصاویر پنل و کاتالوگ روی این دیسک می‌مانند و با استقرار دوباره پاک نمی‌شوند.
3. **متغیرها:** در صفحه برنامه ← «تنظیمات» ← «متغیرها» این‌ها را تعریف کنید:

| متغیر | مقدار |
| --- | --- |
| `DATABASE_URL` | آدرس شبکه خصوصی مرحله ۱ |
| `JWT_SECRET` | رشته تصادفی دست‌کم ۳۲ نویسه، مثلاً خروجی `openssl rand -base64 48`. تغییر آن همه کاربران پنل را خارج می‌کند |
| `PUBLIC_BASE_URL` | آدرس عمومی برنامه با https، مثلاً `https://andishkadeh.liara.run` (بدون `/` پایانی) |
| `SEED_ADMIN_PASSWORD` | رمز اولیه کاربر `admin` (دست‌کم ۸ نویسه) |
| `SEED_OPERATOR_PASSWORD` | رمز اولیه کاربر `operator` |

متغیرهای اختیاری:
- `SEED_ADMIN_USERNAME` و `SEED_OPERATOR_USERNAME`: نام کاربری‌های اولیه.
- `ADMIN_SESSION_HOURS`: مدت نشست پنل.
- `KIOSK_ADMIN_SESSION_MINUTES`: مدت نشست مدیری که از چرخ‌دنده کیوسک وارد می‌شود (پیش‌فرض ۳۰ دقیقه).
- `KIOSK_INSTALLER_URL`: اگر نصب‌کننده کیوسک را جای دیگری گذاشته‌اید.
- `SEED_ON_START=0`: اگر نمی‌خواهید داده اولیه در هر اجرا بررسی شود.

مقادیر زیر در image تنظیم شده‌اند و لازم نیست تعریف شوند:
- `NODE_ENV=production`
- `PORT=3001`
- `TRUST_PROXY=1` (لیارا پشت reverse proxy است)
- مسیر پنل
- `MEDIA_DIR=/app/storage/media`

> سرور در حالت production با مقدار نمونه یا ناامن **اجرا نمی‌شود** و علت را در گزارش برنامه می‌نویسد:
> - `JWT_SECRET` کوتاه یا `CHANGE_ME`
> - `PUBLIC_BASE_URL` بدون https
> - رمز اولیه نمونه

## ۳. استقرار

یکی از دو روش:

**الف) از کامپیوتر خودتان:** Node.js 22 و pnpm (`corepack enable`) را نصب کنید، سپس در پوشه مخزن (بهتر است روی برچسب نسخه، مثلاً `git checkout v1.8.1`):

```bash
pnpm install
pnpm build:shared
pnpm --filter @andishkadeh/server build        # سرور
pnpm --filter @andishkadeh/kiosk build:web     # وب‌اپ مشتری (/)
pnpm --filter @andishkadeh/admin build         # پنل (/admin و /kiosk)
npm i -g @liara/cli
liara login
liara deploy --app andishkadeh
```

اگر برنامه متعلق به یک تیم است، `--team-id <شناسه تیم>` را هم اضافه کنید.

سرور، وب‌اپ و پنل پیش از آپلود ساخته می‌شوند و image فقط آن‌ها را کپی می‌کند. اگر یکی ساخته نشده باشد، ساخت با پیامی که نام آن را می‌گوید متوقف می‌شود.

بسته‌های زمان اجرای سرور در این روش روی لیارا نصب می‌شوند. دسترسی سازنده لیارا به npm کند است و این کار نزدیک به سقف زمان ساخت پلن‌های کوچک (۵ دقیقه) طول می‌کشد. روی لینوکس (یا WSL) می‌توانید بسته‌ها را از پیش آماده کنید تا ساخت لیارا کوتاه شود:

```bash
bash tools/deploy/runtime-bundle.sh            # خروجی: .liara/runtime.tgz (حدود ۸۰ مگابایت)
liara deploy --app andishkadeh --build-arg RUNTIME=.liara/runtime.tgz
```

روش «ب» همه این کارها را خودش انجام می‌دهد و برای استقرار توصیه می‌شود.

**ب) از GitHub (بدون نصب چیزی):**
1. در کنسول لیارا ← «API» یک توکن بسازید.
2. در مخزن GitHub ← Settings ← Secrets and variables ← Actions:
   - secret `LIARA_API_TOKEN` = همان توکن
   - variable `LIARA_APP` = شناسه برنامه (حروف کوچک، همان‌که در آدرس کنسول آمده؛ مثلاً `andishkadeh`)
   - variable `LIARA_TEAM_ID` = شناسه تیم، فقط اگر برنامه متعلق به یک تیم لیاراست

   `LIARA_APP` و `LIARA_TEAM_ID` در تب Secrets هم پذیرفته می‌شوند. حروف بزرگ، فاصله و نقطه اضافه خودکار حذف می‌شوند.
3. Actions ← «Apps» ← «Run workflow» و تیک «Deploy the server and admin panel to Liara». استقرار فقط پس از سبز شدن تست‌ها و آزمون image انجام می‌شود. پس از استقرار، همان اجرا تا ۱۰ دقیقه `https://<برنامه>.liara.run/api/v1/health` را بررسی می‌کند تا همین نسخه پاسخ دهد (لیارا تا بالا آمدن کانتینر جدید، نسخه قبلی را در دسترس نگه می‌دارد). سپس هر سه نشانی `/`، `/admin` و `/kiosk` را آزمون می‌کند. اگر سرور بالا نیاید، علت (مثلاً متغیر نادرست) را به‌صورت خطا نشان می‌دهد.
4. پس از اصلاح متغیرها در کنسول لیارا، دوباره ساختن لازم نیست؛ لیارا برنامه را خودش دوباره اجرا می‌کند. برای بررسی، «Run workflow» را فقط با تیک «Only check the server on Liara» اجرا کنید.

ساخت روی سرورهای لیارا در موقعیت آلمان انجام می‌شود (`liara.json`)، چون دانلود بسته‌ها در موقعیت ایران محدود است.

## ۴. بررسی پس از استقرار

اولین اجرا (migration و داده اولیه) حدود یک دقیقه طول می‌کشد. در این مدت لیارا ممکن است خطای ۵۰۲ نشان دهد.

اگر تنظیمی نادرست باشد، به‌جای ۵۰۲ صفحه «سرور اندیشکده اجرا نشد» با مرحله و علت باز می‌شود (HTTP 503). نمونه‌ها:
- `PUBLIC_BASE_URL: must be the public https:// address`
- «نام کاربری یا رمز عبور در DATABASE_URL نادرست است»
- `Missing env SEED_ADMIN_PASSWORD`

متغیر را در کنسول اصلاح کنید؛ برنامه دوباره اجرا می‌شود. این صفحه پس از ۱۰ دقیقه خودش برنامه را دوباره اجرا می‌کند تا اگر دیتابیس دیر بالا آمده بود، کار ادامه پیدا کند.


1. `https://andishkadeh.liara.run/api/v1/health` باید این را برگرداند: `"status":"ok"`، `"db":"ok"` و `version` همین نسخه.
2. `https://andishkadeh.liara.run/admin` را باز کنید و با `admin` و رمز `SEED_ADMIN_PASSWORD` وارد شوید.
3. از منوی بالا «تغییر رمز» را بزنید. رمز `operator` را هم از «کاربران» عوض کنید.
4. **پس از اولین ورود**، `SEED_ADMIN_PASSWORD` و `SEED_OPERATOR_PASSWORD` را از متغیرها حذف کنید. سرور بدون آن‌ها هم اجرا می‌شود، چون کاربرها ساخته شده‌اند.
5. «خدمات و تعرفه‌ها» ← فیلتر «بدون تعرفه»: قیمت خدماتی را که هنوز تعرفه ندارند وارد و فعال کنید.
6. «تنظیمات» را مرور کنید: مهلت‌ها و سیاست‌های آفلاین.

## ۵. کیوسک ویندوز

1. `https://andishkadeh.liara.run/kiosk` ← ورود ← «ثبت کیوسک جدید». پنجره «اتصال کیوسک» آدرس سرور، شناسه و کلید را نشان می‌دهد.
2. روی کامپیوتر کیوسک، کارت «برنامه کیوسک ویندوز» در همان صفحه نصب‌کننده هم‌نسخه با سرور را دانلود می‌کند (پس از انتشار آن نسخه).
3. پس از نصب، صفحه «راه‌اندازی کیوسک»:
   - آدرس سرور: `https://andishkadeh.liara.run`
   - شناسه و کلید کیوسک
   - چاپگر رسید

جزئیات: [نصب کیوسک ویندوز](windows-kiosk-install.md).

## نگهداری

- **نسخه جدید:** همان روش استقرار را روی برچسب نسخه جدید اجرا کنید. migrationها و داده اولیه جدید هنگام اجرا خودکار اعمال می‌شوند. پیش از آن از پایگاه داده پشتیبان بگیرید.
- **گزارش و خطاها:** کنسول لیارا ← صفحه برنامه ← «لاگ‌ها».
- **خط فرمان داخل برنامه** (مثلاً برای بررسی): `liara shell --app andishkadeh --command=/bin/sh`.
- **پشتیبان:** ر.ک. [پشتیبان‌گیری و بازیابی](backup-restore.md). با آدرس عمومی دیتابیس (اگر فعال باشد) می‌توانید `pg_dump` بگیرید. امکانات پشتیبان‌گیری دیتابیس در کنسول لیارا را هم بررسی کنید.

## عیب‌یابی

| نشانه | اقدام |
| --- | --- |
| خطای ۵۰۲ که با صبر برطرف نمی‌شود، و در لاگ `set: Illegal option -` یا `: not found` | فایل‌ها از ویندوز با پایان خط CRLF آپلود شده‌اند. از نسخه 1.4.1 این مشکل در `Dockerfile` خودکار برطرف می‌شود و `.gitattributes` از تکرار آن جلوگیری می‌کند. آخرین نسخه را بگیرید (`git pull`) و دوباره `liara deploy` کنید |
| صفحه «سرور اندیشکده اجرا نشد» | علت و مرحله روی همان صفحه آمده است. متغیر نام‌برده را اصلاح کنید |
| استقرار با `Build timed out` متوقف می‌شود | ساخت از سقف زمان پلن لیارا گذشته است. از روش «ب» (GitHub) استفاده کنید. این روش بسته‌های زمان اجرا را هم آماده می‌فرستد و ساخت لیارا فقط باز کردن و کپی است. از کامپیوتر: بخش ۳ الف، با `runtime-bundle.sh` |
| استقرار پس از «Pushing...» متوقف می‌ماند | ارسال image به رجیستری لیارا گیر کرده است (مشکل سمت لیارا). اجرای استقرار را لغو و دوباره اجرا کنید. اگر تکرار شد، با پشتیبانی لیارا تماس بگیرید |
| استقرار با `Disk \`media\` does not exist` متوقف می‌شود | در صفحه برنامه ← «دیسک‌ها» یک دیسک با نام دقیق `media` بسازید و دوباره مستقر کنید |
| ساخت (build) با خطای دانلود بسته متوقف می‌شود | `"build": {"location": "germany"}` در `liara.json` بماند |
| برنامه بالا نمی‌آید و در لاگ `Refusing to start in production` است | متغیر نام‌برده در همان پیام را درست کنید |
| `SEED_ADMIN_PASSWORD: set a real value` | رمز اولیه نمونه یا کوتاه است؛ مقدار واقعی بگذارید |
| `Can't reach database server` | برنامه و دیتابیس در یک شبکه خصوصی نیستند، یا `DATABASE_URL` آدرس عمومی/نادرست است |
| `The ... app isn’t running` هنگام استقرار | برنامه را در کنسول روشن کنید و دوباره مستقر کنید |
| تصاویر پس از استقرار ناپدید شدند | دیسک `media` ساخته یا متصل نشده است |
