# پشتیبان‌گیری و بازیابی

سه بخش داده باید پشتیبان داشته باشند:

| داده | محل | اهمیت |
| --- | --- | --- |
| پایگاه داده مرکزی | PostgreSQL (`DATABASE_URL`) | سفارش‌ها، پرداخت‌ها، اشتراک‌ها، کاتالوگ، تنظیمات، سوابق تغییرات — **حیاتی** |
| تصاویر | پوشه `MEDIA_DIR` سرور | تصاویر حوزه‌ها و خدمات (نام فایل = sha256 محتوا) |
| داده محلی هر کیوسک | `%APPDATA%\AndishkadehKiosk\` | سفارش‌ها و رویدادهای ارسال‌نشده و ژورنال پرداخت؛ فقط تا وقتی صف همگام‌سازی خالی نشده حیاتی است |

## پایگاه داده مرکزی

### پشتیبان روزانه

```bash
pg_dump --format=custom --no-owner --file=andishkadeh-$(date +%F).dump "$DATABASE_URL"
```

ویندوز (Task Scheduler، هر شب):

```powershell
$stamp = Get-Date -Format yyyy-MM-dd
& "C:\Program Files\PostgreSQL\16\bin\pg_dump.exe" --format=custom --no-owner `
  --file="D:\backup\andishkadeh-$stamp.dump" "postgresql://andishkadeh:***@localhost:5432/andishkadeh"
Get-ChildItem D:\backup\andishkadeh-*.dump | Where-Object LastWriteTime -lt (Get-Date).AddDays(-30) | Remove-Item
```

- حداقل ۳۰ نسخه روزانه نگه دارید و یک نسخه هفتگی را خارج از سرور (دیسک یا فضای دیگر) ذخیره کنید.
- فایل پشتیبان شامل شماره موبایل مشتریان است. آن را رمزگذاری‌شده و با دسترسی محدود نگه دارید.

### بازیابی

```bash
createdb -O andishkadeh andishkadeh_restore
pg_restore --no-owner --role=andishkadeh --dbname=andishkadeh_restore andishkadeh-2026-10-14.dump
```

پس از بررسی صحت داده:

1. سرویس API را متوقف کنید.
2. `DATABASE_URL` را به پایگاه بازیابی‌شده تغییر دهید یا نام پایگاه‌ها را جابه‌جا کنید.
3. `pnpm db:migrate` را اجرا کنید تا اگر نسخه برنامه جدیدتر است، migrationها اعمال شوند.
4. سرویس را راه‌اندازی کنید.

> بازیابی نسخه قدیمی‌تر یعنی سفارش‌های پس از آن نسخه در سرور نیستند. سفارش‌هایی که کیوسک‌ها هنوز در صف دارند پس از اتصال دوباره ارسال می‌شوند، چون رویدادها با `eventId` ثبت یکتا دارند. سفارش‌هایی که قبلاً تأیید شده و از صف کیوسک پاک شده‌اند برنمی‌گردند. برای همین فاصله پشتیبان‌ها را کوتاه نگه دارید.

### آزمون بازیابی

هر ماه یک بار پشتیبان را روی پایگاه جداگانه بازیابی کنید. API را با همان پایگاه روی پورت دیگری بالا بیاورید و در پنل گزارش فروش یک روز مشخص را با گزارش قبلی مقایسه کنید.

## تصاویر

پوشه `MEDIA_DIR` را با هر ابزار همگام‌سازی فایل کپی کنید (robocopy یا rsync). فایل‌ها هرگز بازنویسی نمی‌شوند، چون نام هر فایل همان sha256 محتواست:

```powershell
robocopy C:\andishkadeh\apps\server\storage\media D:\backup\media /E /XO
```

```bash
rsync -a /opt/andishkadeh/apps/server/storage/media/ /backup/media/
```

اگر تصویری از دست برود، کیوسک‌ها نسخه کش‌شده خود را نگه می‌دارند. کیوسک جدید برای آن مورد تصویر جایگزین حوزه را نمایش می‌دهد تا تصویر دوباره در پنل بارگذاری شود.

## داده محلی کیوسک

- در کارکرد عادی، همه سفارش‌ها و پرداخت‌ها در سرور مرکزی هستند و داده محلی کیوسک فقط صف و کش است.
- پیش از تعویض یا نصب مجدد ویندوز کیوسک:
  1. مطمئن شوید در پنل ← «کیوسک و تجهیزات» برای آن دستگاه «در انتظار» و «ناموفق» صفر است و پرداخت نامشخصی نمانده است.
  2. برنامه را ببندید و پوشه `%APPDATA%\AndishkadehKiosk` را کپی کنید. فایل‌های `kiosk.sqlite`، `kiosk.sqlite-wal` و `kiosk.sqlite-shm` باید با هم کپی شوند.
- **بازیابی روی دستگاه جدید**: پوشه را در همان مسیر قرار دهید و برنامه را اجرا کنید. رویدادهای باقی‌مانده ارسال می‌شوند. ثبت یکتا در سرور مانع سفارش تکراری می‌شود.
- اگر داده محلی از دست رفت و صف خالی بود، کافی است `kiosk.config.json` را دوباره بسازید. کاتالوگ، تصاویر و کش اشتراک‌ها در اولین اتصال دوباره دریافت می‌شوند.
