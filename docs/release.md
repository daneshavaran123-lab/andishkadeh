# انتشار نسخه

هر انتشار یک نسخه واحد برای کل محصول است: کیوسک (ویندوز، وب‌اپ و اندروید)، پنل مدیریت و سرور. نسخه در همه `package.json`ها و در بالاترین بخش [CHANGELOG](../CHANGELOG.md) یکی است و `pnpm version:check` در CI آن را بررسی می‌کند. سرور همین نسخه را در `GET /api/v1/health` و سند API گزارش می‌کند و کیوسک آن را در پنل ← «کیوسک و تجهیزات» نشان می‌دهد.

## فایل‌های هر انتشار

| فایل | کاربرد |
| --- | --- |
| `AndishkadehKiosk-Setup-<نسخه>.exe` | نصب‌کننده کیوسک ویندوز. ر.ک. [نصب کیوسک ویندوز](windows-kiosk-install.md). امضای دیجیتال (code signing) ندارد، پس ویندوز هنگام نصب هشدار SmartScreen نشان می‌دهد |
| `AndishkadehKiosk-<نسخه>.apk` | برنامه اندروید با امضای انتشار. فقط وقتی ساخته می‌شود که secretهای امضای اندروید تعریف شده باشند |
| `AndishkadehKiosk-<نسخه>-debug.apk` | برنامه اندروید با کلید debug، فقط برای آزمایش. روی نسخه قبلی نصب نمی‌شود |
| `AndishkadehKioskWeb-<نسخه>.zip` | وب‌اپ مشتری (`apps/kiosk/dist-web`). سرور آن را از `WEB_APP_DIST_DIR` روی نشانی اصلی `/` ارائه می‌کند |
| `AndishkadehAdmin-<نسخه>.zip` | پنل مدیریت (`apps/admin/dist`). سرور آن را از `ADMIN_DIST_DIR` روی `/admin` ارائه می‌کند |
| `SHA256SUMS.txt` | چکیده SHA-256 همه فایل‌ها، برای بررسی سالم بودن دانلود |
| Source code (zip / tar.gz) | کد همین نسخه که GitHub خودش اضافه می‌کند. سرور از روی آن ساخته می‌شود ([راه‌اندازی سرور](server-setup.md)) |

## مراحل انتشار

1. **نسخه و تغییرات:** `pnpm version:set 1.2.6` نسخه را در همه `package.json`ها می‌نویسد. سپس بخش `## 1.2.6 — <تاریخ>` را بالای `CHANGELOG.md` اضافه کنید. `pnpm version:check` باید همان نسخه را چاپ کند.
2. **بررسی محلی:** `pnpm typecheck && pnpm lint && pnpm knip && pnpm test && pnpm e2e`.
3. **commit و push،** سپس صبر کنید تا اجرای «Apps» در GitHub Actions سبز شود.
4. **ساخت پیش‌نویس:** GitHub ← Actions ← «Apps» ← «Run workflow». شاخه را انتخاب و گزینه «Create a draft GitHub Release from this commit» را تیک بزنید.
   - همه خروجی‌ها دوباره از همان commit ساخته و آزموده می‌شوند.
   - سپس در بخش Releases یک پیش‌نویس `v1.2.6` با فایل‌های بالا ساخته می‌شود. یادداشت انتشار از همان بخش CHANGELOG برداشته می‌شود.
   - اگر این نسخه قبلاً انتشار یا برچسب داشته باشد، کار متوقف می‌شود تا نسخه بالا برود.
5. **بازبینی:** فایل‌ها و یادداشت پیش‌نویس را بررسی کنید. پیش‌نویس برای کاربرانی که دسترسی نوشتن به مخزن ندارند دیده نمی‌شود.
6. **انتشار:** «Publish release». GitHub برچسب `v1.2.6` را روی همان commit می‌سازد.
   - بدون رفتن به صفحه Releases: «Run workflow» با گزینه «Publish the draft GitHub Release of this version» پیش‌نویس همین نسخه را منتشر می‌کند و بررسی می‌کند که نصب‌کننده ویندوز دانلود شود. با تیک هر دو گزینه، پیش‌نویس ساخته و بلافاصله منتشر می‌شود.

## به‌روزرسانی محیط عملیاتی پس از انتشار

1. **پشتیبان:** پیش از هر کاری از پایگاه داده پشتیبان بگیرید ([پشتیبان‌گیری](backup-restore.md)).
2. **سرور و پنل:** روی لیارا، همان استقرار را روی برچسب نسخه انجام دهید ([استقرار روی لیارا](liara-deploy.md#نگهداری)). در نصب مستقیم:
   ```bash
   git fetch --tags && git checkout v1.2.6
   pnpm install --frozen-lockfile
   pnpm build
   pnpm db:migrate          # فقط migrationهای جدید را اعمال می‌کند
   # راه‌اندازی مجدد سرویس
   ```
   پس از راه‌اندازی، `GET /api/v1/health` باید `"version": "1.2.6"` برگرداند. پنل و وب‌اپ با همین build به‌روز می‌شوند. به‌جای ساخت روی سرور می‌توانید فایل‌های zip پنل و وب‌اپ را در مسیرهای `ADMIN_DIST_DIR` و `WEB_APP_DIST_DIR` باز کنید.
3. **کیوسک وب‌اپ:** در بارگذاری بعدی صفحه، اگر سرور در دسترس باشد، نسخه تازه را می‌گیرد. اگر سرور تا ۴ ثانیه پاسخ ندهد، نسخه ذخیره‌شده اجرا می‌شود.
4. **کیوسک ویندوز:** نصب‌کننده جدید را روی همان نصب اجرا کنید؛ داده محلی حفظ می‌شود ([بخش به‌روزرسانی](windows-kiosk-install.md#۸-بهروزرسانی-برنامه-کیوسک)).
5. **کیوسک اندروید:** APK امضاشده انتشار روی نسخه قبلی نصب می‌شود. APK debug نصب نمی‌شود و حذف برنامه داده محلی را پاک می‌کند ([سه نسخه کیوسک](kiosk-platforms.md#اندروید)).

پیش از به‌روزرسانی هر کیوسک، در پنل ← «کیوسک و تجهیزات» مطمئن شوید پرداخت نامشخص یا رویداد ارسال‌نشده‌ای روی آن نمانده است.

## امضای برنامه‌ها

- **اندروید:** برای APK انتشار، secretهای `ANDROID_KEYSTORE_BASE64`، `ANDROID_KEYSTORE_PASSWORD`، `ANDROID_KEY_ALIAS` و `ANDROID_KEY_PASSWORD` را در تنظیمات مخزن تعریف کنید. کلید را جای امنی نگه دارید: بدون همان کلید، نسخه‌های بعدی روی دستگاه‌ها نصب نمی‌شوند.
- **ویندوز:** نصب‌کننده امضا نمی‌شود. برای حذف هشدار SmartScreen گواهی code signing لازم است.

## پیش از بهره‌برداری

انتشار نرم‌افزار به معنی آمادگی بهره‌برداری نیست. [فهرست بررسی پیش از بهره‌برداری](../README.md#۷-فهرست-بررسی-پیش-از-بهرهبرداری) و [موارد باز](open-items.md) را ببینید. مهم‌ترین مورد: **آداپتر کارتخوان بانکی هنوز پیاده‌سازی نشده است.** تا رسیدن SDK بانک، کیوسک فقط با کارتخوان شبیه‌سازی‌شده و نوار «حالت آزمایشی» کار می‌کند و فروش واقعی ممکن نیست.
